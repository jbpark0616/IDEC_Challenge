1. Cnvlutin — 먼저 읽을 논문
Jorge Albericio et al.
Cnvlutin: Ineffectual-Neuron-Free Deep Neural Network Computing
ISCA 2016, DOI 10.1109/ISCA.2016.11
PDF: 03_sparsity_patterns/Albericio_2016_Cnvlutin_ISCA.pdf (13쪽)
원문: https://www.eecg.toronto.edu/~enright/albericio-isca2016.pdf

논문의 문제와 회로
넓은 SIMD가 같은 입력 순서를 강제하면 일부 activation이 0이어도 시간을 줄이기 어렵다.
Cnvlutin은 lane 그룹을 독립 진행시키고, nonzero 값과 원래 위치 offset을 묶어 저장한다.
ZFNAf는 16개 activation을 brick으로 묶고 4bit offset을 추가한다. 고정 brick 위치와
padding을 유지하므로 저장 용량 감소가 목적은 아니다. 해당 activation 저장소는 25% 커진다.
선택한 activation의 offset으로 대응 weight를 읽고 여러 filter에 activation을 재사용한다.
Dispatcher는 16개 독립 메모리 bank에서 brick을 넓게 읽어 Brick Buffer에 보관하고,
각 buffer에서 nonzero 값을 골라 broadcast한다. 다음 brick은 소비 완료 전에 prefetch한다.
window 종료 때는 모든 lane 그룹을 기다리므로 불균형에 따른 유휴 시간은 남는다.

검증과 한계
cycle simulator와 65nm 합성을 사용했고, SRAM buffer는 double-pumping을 가정했다.
zero만 생략한 구성은 baseline 대비 평균 1.37배 성능, 4.49% 면적 증가를 보고한다.
추가 threshold 생략은 별도 실험이다. zero-only 결과와 혼합하면 안 된다.

우리 설계에 대한 해석
가장 가까운 비교 대상은 행별 채널 선택과 그 앞의 공급 버퍼다.
우리는 Winograd 변환 행의 정확한 zero를 4bit mask로 나타내고 V를 dense 형태로 저장한다.
Cnvlutin의 scalar value+offset 형식과 같지는 않다.
참고할 구현: 뱅크별 prefetch pointer, 넓은 read와 작은 소비 단위 분리, 재사용 중 데이터 유지.
주의: double-pumping은 double buffering과 다르다. 현재 ASAP7 SRAM이 MAC 클록의
두 배 속도로 접근 가능하다는 검증 없이 논문의 read/write 처리율을 가져오면 안 된다.

읽을 위치
- III, PDF 3~5쪽: 그룹별 독립 진행의 동기.
- IV-B, PDF 6~9쪽: 실제 구현. Fig. 7 ZFNAf / Fig. 8 Dispatcher는 PDF 8쪽.
- IV-B5, PDF 9쪽: 마지막 그룹을 기다리는 동기화.
- V-A/B, PDF 9~10쪽: 메모리 모델과 성능 비교 조건.

2. Eyeriss v2 — SRAM 공급과 sparse PE를 함께 보는 논문
Yu-Hsin Chen, Tien-Ju Yang, Joel Emer, Vivienne Sze
Eyeriss v2: A Flexible Accelerator for Emerging Deep Neural Networks on Mobile Devices
IEEE JETCAS 2019, DOI 10.1109/JETCAS.2019.2910232
PDF: 05_memory_dataflow_fusion/Chen_2019_Eyeriss_v2_JETCAS.pdf (17쪽)
원문: https://eems.mit.edu/wp-content/uploads/2019/04/2019_jetcas_eyerissv2.pdf

논문의 문제와 회로
레이어별 재사용과 대역폭 요구가 달라 고정 multicast만으로 PE를 채우기 어렵다.
Hierarchical Mesh는 cluster 내부 연결과 cluster 사이 mesh를 결합하고,
unicast, broadcast, grouped/interleaved multicast 등 공급 형태를 바꾼다.
activation과 weight는 CSC 형식으로 처리하며 주소 정보와 data/count를 분리한다.
nonzero activation을 먼저 읽고 대응 nonzero weight를 읽도록 해 불필요한 접근을 줄인다.
의존적인 읽기를 처리하기 위해 PE는 7단계 pipeline과 5개 scratchpad를 사용한다.
두 MAC는 같은 activation을 공유한다. 낮은 sparsity에는 비압축 데이터 처리도 지원한다.

검증과 한계
65nm 배치배선 후 gate-level simulation, 실제 모델 데이터, batch 1 조건의 결과다.
v1/v1.5/v2 비교에서 PE 수·정밀도·global buffer는 맞추지만 v2는 SIMD로 MAC 수가 두 배다.
따라서 v2 개선 전체를 sparsity 하나의 효과로 해석하면 안 된다. 제어·저장소·pipeline
추가로 논리 면적도 증가하며, 높은 sparsity라도 낮은 재사용과 대역폭 병목이 남는다.

우리 설계에 대한 해석
mask를 먼저 확인하고 V/U read를 허용하는 흐름에 참고할 수 있다.
우리 4bit 행 mask는 논문의 CSC 주소·count와 다르므로, CSC 전체를 복사할 필요는 없다.
작은 mask는 FF, 큰 payload는 SRAM으로 분리하는 후보와 read latency 정렬을 검토한다.
레이어 shape마다 통신 방식을 바꿀 이유를 제공하지만 완결 코어 복제가 공유 구조보다
우월하다는 증거는 아니다. 내부 PE cluster를 우리 Winograd 코어와 동일시하지 않는다.

읽을 위치
- III-C, PDF 6~8쪽, Fig. 8~12: 통신 모드와 router 구성.
- IV-A, PDF 9~11쪽, Fig. 16~17: CSC와 sparse PE.
- V, PDF 11~14쪽, Table IV~VI: 검증 방법, 비교 구성, 병목.
- 특히 PDF 11쪽 Fig. 17과 PDF 12쪽 Table V를 함께 읽는다.

3. MAERI — 여러 mapping과 partial-sum reduction의 비용을 보는 논문
Hyoukjun Kwon, Ananda Samajdar, Tushar Krishna
MAERI: Enabling Flexible Dataflow Mapping over DNN Accelerators via Reconfigurable Interconnects
ASPLOS 2018, DOI 10.1145/3173162.3173176
PDF: 05_memory_dataflow_fusion/Kwon_2018_MAERI_ASPLOS.pdf (15쪽)
원문: https://bpb-us-e1.wpmucdn.com/sites.gatech.edu/dist/c/332/files/2018/01/maeri_asplos2018.pdf?bid=332

논문의 문제와 회로
고정 연결망에서는 연산량이 충분해도 서로 다른 크기의 reduction을 병렬 배치하기 어렵다.
MAERI는 multiplier/adder에 switch를 결합하고 입력 분배망과 reduction/collection 망을 나눈다.
분배망은 multicast용 tree와 인접 multiplier 사이 forwarding을 사용한다.
Augmented Reduction Tree는 중간 adder 사이 forwarding과 상위 link 대역폭을 보강한다.
연속된 multiplier 집합을 하나의 Virtual Neuron으로 구성해 여러 크기의 누산을 배치한다.
Virtual Neuron은 우리처럼 완결된 Winograd 코어를 복제한 단위가 아니다.

검증과 한계
28nm 합성·배치배선 비교와 mapping/latency 평가를 제시한다.
같은 연산기 수 조건과 같은 면적 조건을 따로 비교한다.
연결망 대역폭을 줄이면 활용률과 전력 사이의 trade-off가 발생하며,
동일 연산기 수에서 단순 systolic 구조의 면적·전력이 작은 결과도 명시한다.
유연한 mapping이 자동으로 모든 workload의 에너지 효율을 개선하는 것은 아니다.

우리 설계에 대한 해석
입력 multicast만으로 C sharding을 완성할 수 없고, 부분합 합산 경로가 필요함을 설명한다.
우리는 우선 목적 코어 FIFO -> local adder/accumulator로 reduce하는 작은 구조부터 비교한다.
MAERI의 전체 ART를 처음부터 구현하는 것은 현재 2~4코어 목표보다 큰 범위다.
K/T 분할과 C 분할의 통신량, 부분합 폭, 합산 대기, 재설정 비용을 구분해 계수한다.

읽을 위치
- 2.3~3, PDF 4~6쪽, Fig. 3~7: 분배와 reduction의 차이.
- 4.1, PDF 6~7쪽: Virtual Neuron 구성.
- 5, PDF 10쪽, Table 3: 실제 비교 조건.
- 6, PDF 11~13쪽: dense/sparse mapping과 대역폭 영향.

우리 프로젝트에서의 읽는 순서와 확인할 항목
Cnvlutin -> Eyeriss v2 -> MAERI. SCNN은 압축 데이터 재사용의 기존 비교 자료로 유지한다.
세 논문 모두 우리 F(2,3) 변환 행 검출의 신규성을 직접 증명하지 않는다.

먼저 단일 코어에서 확인할 것:
1) 지정주제처럼 V와 mask를 같은 수명으로 유지하고 K 방향 재사용 후 반환하는가?
2) mask를 보고 실제 SRAM 읽기/연산 투입이 줄어드는가?
3) skip으로 빨라진 소비를 prefetch가 따라가는가? FIFO empty와 bank conflict를 분리해 측정한다.
4) dense+mask 방식과 nonzero 목록 방식의 metadata·선택기·공급 비용은 얼마인가?

멀티코어에서 추가할 비교:
1) multicast 수신 stall, 입력 복제량, V 재변환 횟수.
2) layer별 K/T mapping 전환의 재분배 비용 포함 latency.
3) C 분할 추가 시 부분합 전송량·합산 자원·동기화 비용.
4) 같은 총 MAC/SRAM/포트 대역폭/외부 대역폭의 공유 구조와 비교.
지정주제의 1pixel/cycle 공급 한계나 현재 SRAM 물리 정합 문제는 이 논문으로 해결된 것이 아니다.
