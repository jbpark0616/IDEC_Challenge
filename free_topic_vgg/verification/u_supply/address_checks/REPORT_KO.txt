U 밀집 주소·물리 용량 기준 상주 검증
==================================
이번 수정은 자유주제에만 적용했다. 지정주제 RTL은 변경하지 않았다.

변경
- full-model host가 bank14/주소4에 1을 써 U 밀집 배치를 선택한다.
- U8 출력 하나의 bank 점유량은 ceil(Cin/2) 워드이다.
- 상주는 Cout_local * ceil(Cin/2) <= 1024로 판정한다.
- 출력 16개 제한과 U의 최소 128채널 stride를 제거했다.
- MAC은 물리 U 시작 주소를 받아 채널별 offset을 더한다.
- 이전 fixture는 주소4=0으로 기존 메모리 배치를 검증할 수 있다.

경계 검증: 입력 [1,4,4,Cin], 담당 출력 Cout_local
Cin / Cout | bank당 U 워드 | 상주 | 전체 U payload 쓰기 (64비트 워드)
3   / 32   | 64            | 가능 | 256 (초기 적재만)
3   / 128  | 256           | 가능 | 1024 (초기 적재만)
63  / 32   | 1024          | 가능 | 4096 (초기 적재만, 용량 경계)
65  / 32   | 1056          | 불가 | 16896 (4공간 타일에서 재적재)

4사례 x bypass OFF/ON x 상주 요청 OFF/ON = 16회 통과.
각 공급 모드에서 출력 896워드가 independent numpy oracle와 일치했다.
stale commit 거부, V 마지막 사용 후 release, 입력·출력 backpressure를 검사했다.
기존 U8/V8 12사례도 밀집 배치로 48회 통과했다 (공급 모드당 694워드).
V16 회귀 20회는 이전 사이클·투입·대기 수치까지 일치했다.
양자화 16328조합, full-model TB lint, 16코어 Conv→FC1→FC2→FC3→Conv
전환 검증도 통과했다. FC 검증은 202개 출력 워드 일치, 최종 class=8이다.

주의: 상주 중에도 bias/scale metadata 전환과 commit 대기는 남는다.
현재 변경이 임의 텐서 형상 전체 지원을 완성한 것은 아니다.
기존 명령 필드 폭·metadata window·activation 제약은 U_STORAGE.txt 참고.
PPA 및 전체 모델 실행 시간은 이번 검증에서 측정하지 않았다.

현재 VGG 적용 범위
Conv1~5: 밀집 배치에서 각 bank의 점유량은 8,128,256,512,1024워드.
Conv6~7: 2048워드, Conv8:4096워드, Conv9~13:8192워드가 필요하므로
각 bank의 1024워드 용량을 넘는다. 기존 상주 정책 대비 전체 상주 가능한
VGG 레이어 집합은 같으며, 이번 수정만으로 후반 재적재가 없어지지는 않는다.
출력 16개 제한 제거는 임의의 작은 Cin/큰 Cout 조합에서도 실제 용량만큼
사용할 수 있게 한 수정이다. VGG 전체 속도 개선으로 과장하지 않는다.
