단일 코어 요청 즉시 공급 TB — 2026-10-31
=====================================
RTL 변경 없음. verification/raster_restore/run.py --immediate로 재현.
기존 raster_restore 로그는 보존. 기능 stress TB도 그대로 보존.

성능용 변경:
- weights_waiting 요청/descriptor를 관찰하여 다음 구동 edge부터 즉시 서비스.
- 상태 레지스터 polling 제거. 내부 관찰은 read-only이며 hierarchy write/force 없음.
- 메타데이터/가중치/commit은 정상 mem_valid/mem_ready 호스트 포트로만 전송.
- 연속 write 사이의 TB idle cycle 제거 (최대 64-bit word/cycle).
- stale commit 주입, 고의 5-cycle 지연, 주기적 output stall 제거.
- 실제 SRAM 응답/포트 arbitration 및 DUT backpressure는 그대로.
따라서 외부 소프트웨어 지연 없는 요청 응답 모델이지 실제 외부 IP 실측이 아님.

입력 [1,4,4,3], initial preload 제외한 core execution cycles:

128 OFF     5801                5769              7977

두 공급 경로, K 2조건, sparse OFF/ON 총8회 PASS.
각 경로 최종 출력 536 word 및 생성 tile stream 독립 oracle 일치.
SRAM source read는 기존18회, raster6회로 동일.
K128 raster의 weight_wait는 OFF/ON 모두 1575 cycles = 63 * 25.
25는 요청당 24개 metadata word(8개 bias/mult/shift) + commit 1개.
이는 더 이상 고의 TB stall이 아니며 현재 제어 인터페이스의 실제 전송 비용.
K128 raster sparse 절감 = (5769-5257)/5769 = 8.8750%.
이 결과는 3채널 작은 입력의 단일 코어 검증이며 전체 VGG/16코어 결과가 아님.
