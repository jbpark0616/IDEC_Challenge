16코어 전체 합성 결과 분석
=========================

범위: 표준셀 매핑 + 배치배선 전 STA. 실제 배치/배선/CTS/전력 검증 아님.
전체 계산 코어 16개, SRAM 192개, ICG 160개. synth check 0 problems.
총 소요 3471초(57분51초). 계산 코어를 한 번 매핑하고 계층으로 재사용.
완료 STA 단계의 peak memory는 약10.38GiB로, 매핑 단계보다 높았다.

면적 (Liberty 면적 합, um^2)
  전체                 738434.615940
  SRAM                 453093.212160 (61.36%)
  표준셀               285341.403780 (38.64%)
  계산 코어 표준셀 x16  270627.428160
  상위/주변 표준셀       14713.975620
  계산 코어 내부 SRAM은 8개/코어이며 A/B 4개/코어는 상위에 있다.
  전체 SRAM 용량: 192 x 8KiB = 1.5MiB.
  전체 FF 196562개. 계산 코어 모듈당11184개, 상위/주변17618개.
  면적 합0.7384mm^2는 라우팅 공간/클록트리/전원망을 포함한 die 면적이 아니다.

타이밍
  목표 주기1000ps. WNS -638.28ps.
  report_clock_min_period: 1638.28ps / 610.39MHz.
  최장 경로 시작: u_cluster.fc_mode FF
             끝: host_ready 출력
  데이터 도착1438.28ps, 외부 출력 지연 조건200ps -> 요구 주기1638.28ps.
  경로에 따라 관측한 누적 도착 시각:
    FC 모드 선택/분배 및 코어 output_word[0] : 471.43ps
    출력 주소 덧셈/뱅크 중재 후 output_ready : 805.30ps
    코어 내부 ready 논리 후 core_mem_ready[4] : 1286.61ps
    상위 선택 후 host_ready                  : 1438.28ps
  위 구간은 해당 단일 STA 경로의 관측값이며 전체 경로 분포 통계가 아니다.
  MAC 곱셈 자체가 이 최장 경로의 원인은 아니다.
  모드 신호 분배, 출력 주소/중재, ready 반환이 조합으로 길게 연결된다.

다음 개선 후보 (이번 분석에서는 RTL 수정하지 않음)
  1. 출력 주소/데이터/valid를 함께 보관하는 elastic 경계로 SRAM writer
     중재와 계산 코어 ready 반환을 분리할 수 있는지 검토.
  2. host request 수락과 내부 요청 실행을 소형 요청 버퍼로 분리할 수
     있는지 검토. ready만 레지스터로 바꾸면 요청 유실 위험이 있으므로
     payload 보관과 backpressure 규칙까지 같이 설계해야 한다.
  3. fc_mode 고팬아웃 분배와 셀 구동력은 배치 후 버퍼링/리사이징 대상.
  상위 여러 경로를 더 추출한 뒤 효과를 판단해야 하며 1GHz 달성 보장은 없다.
  모드가 안정적이라는 이유만으로 false path로 제거하지 않는다.

해석 제한
  기존 단일 코어560MHz와 이번 전체610MHz는 구조/매핑 조건이 달라
  순수 RTL 변경에 의한 주파수 향상률로 비교하지 않는다.
  멀티캐스트 단독2.14GHz도 전체 가속기 주파수로 사용하지 않는다.
  SRAM LEF의 sdel[0:4] 핀이 Liberty에 없다는 경고와 coreSite 경고가 있다.
  set_input_delay가 clock 자체에 적용되는 경고도 있다. SDC 정리가 필요하다.
  이번 제시된 host_ready 경로의 출력 지연200ps는 실제 STA 보고서에서 확인했다.
  표준셀 RVT FF와 SRAM 모델 코너 정합성 및 물리 구현을 검토하기 전에는
  signoff Fmax로 주장하지 않는다. 전력/이미지당 에너지는 이번 결과에 없다.
